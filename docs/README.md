# Moon — что установить и как проверить

В этом архиве два обязательных исправления и один необязательный патч.
Ничего программировать и редактировать вручную не нужно: только загрузить ZIP
в Яндекс Облако.

| Что | Версия | Файл | Обязательно? |
|---|---|---|---|
| Moon Vision | **4.1.14** | `Moon-Vision-4.1.14-install.zip` | да |
| Moon Skill (Алиса) | **3.4.3** | `Moon-Skill-3.4.3-install.zip` | да |
| Moon Knowledge | 0.9.3 | `Moon-Knowledge-0.9.3-OPTIONAL.zip` | нет, отдельный эксперимент |

APK и Android не менялись. Переменные окружения и настройки облака не менялись.

---

## 1. Что исправлено (коротко)

1. **Пропадал новый короткий вопрос.** Если Алиса уже что-то «собирала»,
   вопрос из трёх слов («Кто такие Вудуисты?», «Где находится Пасифика?»)
   считался просьбой «ну что там» и не доходил до сервера. Теперь так считаются
   только «и что?», «дальше», «ну».
2. **Зависание «processing_deep» (случай Пасифики).** У глубокого разбора не
   было ограничения по времени: функция могла не успеть сохранить результат, и
   запись оставалась «в обработке» навсегда. Теперь у разбора есть бюджет,
   результат сохраняется всегда, а задача старше 5 минут честно закрывается.
3. **Диагностика больше не врёт.** Раньше статус «просрочено» не сохранялся
   (слияние состояния откатывало его назад), поэтому в `?diag=1` висела
   «живая» задача, хотя её уже никто не считал. Теперь статус пишется напрямую.
4. **Ответы разных пользователей не мешают друг другу.** Раньше смена игры
   одним пользователем «прятала» ответ другого и отменяла его вопросы.
5. **Профиль пользователя не может быть общим.** Убрана подстановка
   `application_id` (он одинаков у всех), из-за которой разные люди могли
   получить один профиль.
6. **«Я теперь играю в Minecraft»** распознаётся как смена игры.
7. **Токен** больше не уходит в адрес запроса (он попадал в логи).
8. **«Кто из героев сильнее?»** больше не считается командой показа.
9. **«Просрочено» с сервера** понимается сразу — без лишнего «Собираю ответ».
10. **Время ответа** приведено к лимиту Алисы 4,5 с с запасом (по официальной
    документации в 4,5 с входит и сеть).

Подробный разбор с доказательствами и таблицей таймаутов — в `AUDIT-REPORT.md`.

## 2. Установка

Порядок: **сначала Vision 4.1.14, потом Skill 3.4.3.**
Адреса (Webhook URL) навыка, адрес функции и точка входа `index.handler`
**не меняются**.

### Шаг 1. Moon Vision 4.1.14

1. Консоль Яндекс Облака → **Cloud Functions**.
2. Выберите функцию, в которую Moon Skill отправляет вопросы (Moon Vision).
3. Вкладка **Редактор** → **Загрузить ZIP** → `Moon-Vision-4.1.14-install.zip`.
4. **Создать версию** → сделать её текущей.
5. Runtime остаётся `nodejs22`, точка входа — `index.handler`.

В архиве три файла в корне: `index.js`, `moon-vision-core.js`, `VERSION`.
Распаковывать вручную не нужно.

> Если в облаке сейчас 4.1.11 — это нормально: 4.1.14 заменяет её целиком
> (это полная сборка, а не патч).

### Шаг 2. Moon Skill 3.4.3

1. В той же консоли выберите функцию навыка Алисы (Moon Skill).
2. **Редактор** → **Загрузить ZIP** → `Moon-Skill-3.4.3-install.zip`.
3. **Создать версию** → сделать её текущей. Точка входа — `index.handler`.

В архиве один файл: `index.js`.
Переменная `MOON_TOKEN` остаётся как была (Skill теперь отправляет её
заголовком `X-Moon-Token`; если развёрнутый Vision её не примет, навык сам
один раз вернётся к старому способу `?token=` — ничего настраивать не нужно).

### Шаг 3 (необязательно). Moon Knowledge 0.9.3

Только если хотите, чтобы для игр с Fandom подключалась именно **русская**
вики (`ru.cyberpunk.fandom.com`), а не английская с переводом ответа.
Это отдельный патч: он меняет выбор источника. Поставьте, проверьте один
вопрос про Cyberpunk 2077 и сравните с прежним ответом; при сомнении верните
предыдущую версию Knowledge.

## 3. Проверка после установки

### 3.1. Версия Vision

Откройте диагностику функции так, как вы делали это раньше (тот же токен).
В ответе должно быть:

```
"ver": "4.1.14"
```

### 3.2. Версия Skill

Задайте Алисе любой вопрос и откройте логи функции навыка. В строке
`{"s":"moon",...}` должно быть:

```
"v":"9.6-a-v3.4.3"
```

### 3.3. Проверка в Алисе (по одной фразе)

1. «Алиса, запусти Лунного Ассистента» → приветствие.
2. «Я играю в Cyberpunk 2077» → «Принято, игра: Cyberpunk 2077».
3. «Кто такие Вудуисты?» → ответ по игре (не «Ещё собираю»). Это контрольный
   сценарий, он работал и должен работать дальше.
4. «Где находится Пасифика?» → либо ответ, либо «Собираю ответ», а затем на
   «Ну что там?» — готовый ответ **или** честное «Ответ не успел собраться.
   Спроси ещё раз.» Главное: **не должно быть бесконечного «Ещё собираю»**.
5. «Покажи Пасифика на карте» → визуальная команда (просит стрим/кадр).
6. «Кто из героев сильнее?» → обычный вопрос (не просит показать экран).
7. «Я теперь играю в Minecraft» → «Принято, игра: Minecraft».
8. «Ну что там?» → забирает готовый ответ, если он был.
9. «Хватит» → прощается и закрывает навык.

Проверьте ещё два важных случая:

* «Я играю в The Witcher 3. Где найти Геральта?» — игра должна отделиться от
  вопроса, а в Vision уйти только сам вопрос;
* два разных пользователя (два аккаунта Алисы): у каждого своя игра, ответы
  не должны смешиваться.

### 3.4. Что смотреть в диагностике после вопроса о Пасифике

Через 1–2 минуты после вопроса в `?diag=1`:

* `status` записи — `deep_ready` (готово) или `expired` (истекло),
  **не** `processing_deep` дольше пары минут;
* `kb` — `ok` (ответ из базы) или конкретная причина (`no_evidence`,
  `timeout`, `insufficient_evidence`, `model_error`);
* `sources` — сколько статей нашлось;
* `claim_age_s` не должен расти бесконечно.

Если запись всё же зависла — пришлите строку из диагностики и строки логов
функции за это время (без токена). Это единственное, что нельзя проверить
без облака.

### 3.5. Проверьте таймаут функции (важно)

Cloud Functions → ваша функция Vision → **Версия** → **Таймаут**.
Он должен быть **не меньше 90 секунд** (внутренний бюджет разбора — 75 с).
Если там 60 с или меньше, задайте в функции переменную окружения
`MOON_DEEP_BUDGET_MS` примерно на 10 000 меньше таймаута
(например, `50000` при таймауте 60 с). Это необязательная настройка:
без неё всё работает, но при очень коротком таймауте разбор будет обрываться.

Если таймаут функции менять нельзя — ничего страшного не произойдёт:
игрок получит короткий ответ или честное «не успел собраться», вечного
ожидания не будет.

## 4. Если что-то пошло не так (откат)

В папке `rollback/` лежат предыдущие сборки:

* `Moon-Skill-3.4.1-install.zip` — навык как был;
* `Moon-Vision-4.1.12-candidate.zip` — кандидат 4.1.12 из репозитория
  (состояние **до** этих правок).

Откат: консоль → функция → **Редактор** → **Загрузить ZIP** → архив из
`rollback/` → **Создать версию** → сделать текущей.

> В наборе нет исходников развёрнутого **4.1.11**. Если нужно вернуться именно
> к нему, используйте ваш собственный сохранённый архив 4.1.11.

Порядок отката при сомнениях: сначала Skill (он совместим с любой версией
Vision), затем Vision.

## 6. Как запустить тесты самому (необязательно)

Нужен Node.js 22. В корне распакованного архива:

```
node --test tests/skill.test.js tests/vision.test.js tests/kb.test.js tests/integration.test.js
```

Ожидаемый результат: `# tests 67`, `# pass 67`, `# fail 0`.
Тесты работают без интернета: Облако, база знаний и модель подменены в памяти.

Можно прогнать те же тесты на старых версиях и увидеть, что они падают
(это доказательство, что тесты действительно ловят найденные дефекты):

```
MOON_SKILL_PATH=$PWD/sources-before/skill-3.4.1/index.js node --test tests/skill.test.js
MOON_CORE_PATH=$PWD/sources-before/vision-4.1.12/moon-vision-core.js node --test tests/vision.test.js
```

Ожидаемо: 27 pass / 8 fail и 17 pass / 6 fail соответственно.
